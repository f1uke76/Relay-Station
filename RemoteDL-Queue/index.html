PAT 填写指引 · 逐项怎么填 / 对应什么效果

先用 f1uke76 账号登录 GitHub，再点「一键获取令牌」打开预填创建页。 链接已预填名称、无期限和两项权限，但「Repository access」仓库范围必须自己确认 —— 这是最常见的 403 原因。

1
Token name / Description：随便填
预填的是 RemoteDL。只是给自己辨认用，不影响功能，也不用和别人一致。
2
Resource owner：选 f1uke76（本人）
选成组织会列不出这两个仓库，后面就没法勾仓库范围。
3
Expiration：选 No expiration（无期限）
GitHub 会黄字提醒设有效期，个人自用可忽略。若选 30 / 90 天：到期后网页与 App 全部报 401， 要重新生成；先「删除所有」清空 pat.md 登记，再保存新令牌，其它端启动时自动同步。
4
Repository access：两个仓库都要覆盖
照截图选 All repositories 最省事：一次覆盖现有和以后新增的仓库，但权限面较大。 也可选 Only select repositories 只勾 RemoteDL + Relay-Station（权限最小， 以后加新仓库要回来补勾）。
只勾 RemoteDL → pat.md 能读写，但添加链接 / 进度回传 403； 只勾 Relay-Station → 队列能写，但「保存」写 pat.md 失败，其它设备拿不到令牌。
5
Issues：Read and write
用于本页创建下载 Issue、取消 / 删除记录，以及 App 每约 5 秒 PATCH 回写进度。 只给 Read → 列表还能刷新，但加不了链接、进度写不回去；完全不勾 → App 仍可匿名读队列继续下载， 但所有写操作都失效。
6
Contents：Read and write
用于读写私有库 pat.md：保存登记、删除清空、其它端启动同步。 只给 Read → 「验证」能读到文件，但「保存」会因写权限不足失败。
7
Metadata：Access: Read-only
GitHub 强制的必备项，页面已自动带上，不用改；其余权限保持 No access 即可。
8
Generate token：复制整串，回来验证再保存
令牌只显示一次，复制 github_pat_... 整串 → 粘贴到本页或 App → 「验证」（看账号、有效期、中转库与 pat.md 是否可读）→「保存」（登记到 pat.md； 若已有仍有效的登记则不覆盖，会提示改用登记的那枚）。 其它设备打开 pat.md 复制同一串即可，不要重复生成。

已有令牌不用重建：到 GitHub 编辑这枚令牌，补勾两个仓库与 Issues / Contents 两项权限， 令牌字符串不变，各端无需重新填写。

安全：pat.md 是明文且留在 git 历史里，私有库切勿转公开； 泄露就去 GitHub 撤销（Revoke），并在各端点「删除」。
